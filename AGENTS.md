# Repository Guidelines

## Project Structure & Module Organization

This C#/.NET 10 utility handles DOS 3.3/ProDOS disks, 6502 assembly, and Applesoft BASIC. Consult `PLAN.md` for release checks. The layout is:

- `src/A2Utils.Core/`: disk operations and adapters; `Assembly/`, `Basic/`, and `Programs/` contain program codecs and headers.
- `src/A2Utils.Cli/`: `a2 disk`, `asm`, and `basic` commands and output formatting.
- `examples/`: original assembly and Applesoft source programs.
- `tests/A2Utils.Core.Tests/` and `tests/A2Utils.Cli.Tests/`: library and command tests.
- `tests/TestData/`: redistributable disk fixtures with provenance, expected catalogs, and hashes.
- `docs/decisions/` and `docs/formats/`: architecture decisions and format references.
- `third_party/CiderPress2/`: pinned DiskArc/CommonUtil sources and notices; preserve upstream formatting.

Keep disk logic independent of console output and host filename conventions. Use the DiskArc adapter; record dependency changes in the architecture decision.

## Build, Test, and Development Commands

Use the SDK pinned in `global.json`. Run from the repository root:

```sh
dotnet restore A2Utils.slnx --locked-mode           # Restore pinned dependencies
dotnet build A2Utils.slnx -c Release                # Compile
dotnet test A2Utils.slnx -c Release                 # Run tests
dotnet run --project src/A2Utils.Cli -- disk --help  # Show CLI help
dotnet format A2Utils.slnx --verify-no-changes --exclude third_party
```

`dotnet format` checks source formatting. `pwsh -File eng/Package.ps1` tests and builds local tool and self-contained packages.

## Coding Style & Naming Conventions

Use four-space indentation, Allman braces, file-scoped namespaces, and nullable reference types. Use PascalCase for types and public members, camelCase for parameters/locals, and `_camelCase` for private fields. Match filenames to primary types; suffix asynchronous methods with `Async`. Use explicit endian-aware binary parsing and validate offsets before access. Follow `.editorconfig`.

## Testing Guidelines

Use xUnit and name tests `Operation_Condition_ExpectedResult`. Cover sector-order round trips, metadata preservation, malformed images, allocation boundaries, CLI exit codes, and failed writes. Every write operation needs preservation and failure-path coverage; no percentage threshold is established. Validate against independently produced fixtures, not only images generated by the chosen engine.

## Disk Image Integrity

Treat extensions as hints. Preserve untouched bytes and metadata. Stage writes in temporary files, validate before replacement, and back up explicit in-place updates. Never modify reference fixtures directly.

## Commit & Pull Request Guidelines

Use concise imperative commit subjects, such as `Add DOS catalog reader`. Keep changes focused. PRs should explain the problem, resulting behavior, affected formats, and validation performed; link relevant issues. Update `PLAN.md` when scope or architecture changes.
