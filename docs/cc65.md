# C and ca65 compilation

The optional `cc compile` command uses an existing cc65 installation to compile
C or ca65 assembly into a validated AppleSingle program. A2Utils does not bundle
or automatically install a compiler. Install cc65 from the
[upstream project](https://cc65.github.io/) and keep its tools, target libraries,
headers, and linker configurations together.

```sh
a2 cc compile main.c --compiler /path/to/cc65/bin/cl65 --target apple2 --to hello.as --json
```

The supported compiler targets are `apple2` and `apple2enh`; `apple2` is the
default. Choose `apple2enh` only for an enhanced IIe/IIc-compatible target. Use
`--expected-version` with the exact combined stdout/stderr of `cl65 --version`
to refuse unexpected compiler versions. The compiler path is optional when
`cl65` is on PATH. CLI paths are relative to the current working directory.

`--project-root` defaults to the main source's directory. Local source and
include paths must remain beneath that root. The wrapper copies supported
project files to a temporary directory before starting cl65, protecting source
and adjacent assembly/object files from compiler intermediate writes. The trusted
system temporary root is resolved to its physical directory so macOS's `/var`
alias is usable; this does not relax link rejection for project or compiler paths.
See the [upstream cl65 guide](https://cc65.github.io/doc/cl65.html) for compiler
and linker behavior.

Main assembly sources may use `.s`, `.asm`, or `.a65`. An assembly program using
the target's C runtime must declare `.forceimport __STARTUP__` and export `_main`,
as required by cl65; merely defining `_main` does not pull in that startup code.

The snapshot includes `.c`, `.h`, `.s`, `.asm`, `.a65`, `.inc`, and `.bin` files.
Hidden directories and directories named `artifacts`, `bin`, `obj`,
`node_modules`, and `third_party` are excluded. There are limits of 4096 source
directories, 4096 files, 4 MiB per source file, and 64 MiB total source data.
Keep the project root focused on the C program rather than an entire unrelated
repository. Quoted project includes must remain within the project root.
Macro-based includes remain unsupported. A project-local `linkerConfig` selects
a validated custom ld65 configuration, described below.
System headers use the installed compiler's normal include search behavior.
Include validation handles C comments and continued directives, as well as ca65
labels before directives. C textual includes must use `.c` or `.h`; ca65 textual
includes must use `.s`, `.asm`, `.a65`, or `.inc`. Binary inputs use `.incbin`.
This keeps every project file interpreted as source within the corresponding
validated source format. Use forward slashes and literal characters in ca65
include paths. The adapter accepts default ca65 syntax; computed filenames,
continued assembly lines, and compatibility directives (`.feature`/`.linecont`)
are unsupported. ca65 semicolon comments do not continue onto the next line.

`--timeout` defaults to 60 seconds per compiler process. Timeout and cancellation
terminate the compiler process tree. Compiler output capture is bounded. A
failed build does not replace an existing destination. `--to` must differ from
the input and staged dependencies, and `--overwrite` explicitly permits replacing
an existing output after AppleSingle validation. Generated-workspace cleanup uses
bounded retries and never masks the compile result; a persistent host lock can
leave a uniquely named `a2-cc65-*` directory in the system temporary directory.

The `cc.compile` JSON result provides `outputPath`, `format: "applesingle"`,
compiler `version`, `target`, file type, auxiliary type, payload length, SHA-256,
linker `map`, VICE-format `labels`, and input hashes. `Cc65Result` additionally
provides parsed `symbols`, `segments`, `diagnostics`, `compilerPath`, and
`toolchainInputs`. Symbol names preserve C's leading underscore and remove the
VICE record's leading dot: `._main` becomes `_main`. Projects import these symbols
into the same symbolic assertion/debugging mechanism used by native assembly.
Compiler diagnostics retain severity, original file path, line, and column when
the compiler provides them; paths under the isolated source directory map back to
the project. Unlocated linker messages remain unlocated.

Set `toolchainRoot` to fingerprint its `bin`, `include`, `asminc`, `lib`, and `cfg`
trees as well as the resolved compiler executable. The wrapper sets `CC65_HOME`
to this root, prepends its `bin` to the compiler process's PATH, and removes
inherited `CC65_INC`, `CA65_INC`, `LD65_LIB`, `LD65_OBJ`, and `LD65_CFG` overrides.
This is an explicit selection of the configured distribution. Distribution
inputs reject links and are bounded to 4096 files, 64 MiB per file, and 256 MiB
total; changes during compilation fail the build. With no root, the existing
compiler environment is preserved and `cc65.toolchain_partial` identifies the
incomplete fingerprint. External subprocesses selected outside the configured
distribution or custom compiler behavior are not a hermetic build guarantee.

Project manifests support additional source files, include directories, and
preprocessor definitions through a `cc65` configuration:

```json
{
  "cc65": {
    "compiler": "/path/to/cc65/bin/cl65",
    "target": "apple2",
    "expectedVersion": "cl65 V2.19 - Git e11fb5c",
    "timeoutSeconds": 60,
    "optimize": true,
    "additionalSources": ["helper.c"],
    "includes": ["include"],
    "defines": ["FEATURE=1"]
  },
  "files": [
    { "source": "main.c", "path": "HELLO", "kind": "cc65" }
  ]
}
```

This fragment belongs within an A2Utils project manifest. Compiler/source/include
paths in that manifest are relative to its directory. Use your installed
compiler's actual version string. The project builder extracts AppleSingle
metadata and checks it against the requested Apple II target; callers should
retain that metadata rather than guessing a load address for C output.

## Custom linker configurations

```json
{
  "cc65": {
    "compiler": "/path/to/cc65/bin/cl65",
    "toolchainRoot": "/path/to/cc65",
    "linkerConfig": "linker/apple2-custom.cfg",
    "segmentBanks": { "AUXDATA": "aux" }
  }
}
```

The configuration must remain inside the project root. It is copied and hashed
with source inputs; cl65 receives the staged path with `-C`. Supported sections
are `MEMORY`, `SEGMENTS`, `SYMBOLS`, `FEATURES`, and `FILES`. Configurations use a
single output: `MEMORY` file attributes may select `%O` or `""`, and `FILES`
entries may refer only to `%O`. Other output strings, interpolation, includes,
and nested configuration syntax are refused before launching the compiler.
The compiler still validates linker expressions and assignments, and the final
result must be a valid AppleSingle program. Start from an Apple II configuration
that includes its executable header. Raw multi-output ROM layouts are outside
this adapter's output contract.

The upstream [ld65 guide](https://cc65.github.io/doc/ld65.html) explains MEMORY
areas, segment types and distinct LOAD/RUN addresses. A2Utils parses the segment
list's runtime addresses and the selected configuration's BSS/zero-page types.
`segmentBanks` assigns physical banks to named runtime segments; it does not emit
copy or switching code. Missing segment names are errors. The stock Apple II
configuration's `LC` segment maps to `lc2`; custom configurations must declare
their own bank mapping. AppleSingle's payload remains in its normal load bank.

Runtime reports include BSS, zero page, and the C software stack when exported
`__HIMEM__`/`__STACKSIZE__` bounds are available. The stock cc65 Apple II layout
uses `$80-$99` for saved zero-page workspace and reserves a software stack below
HIMEM. See the upstream [Apple II configuration](https://github.com/cc65/cc65/blob/master/cfg/apple2.cfg)
and [startup routine](https://github.com/cc65/cc65/blob/master/libsrc/apple2/crt0.s).
Missing segment/stack information produces diagnostics instead of inventing a
footprint. Explicit heap, stack and other budgets are described in
[runtime memory accounting](runtime-memory.md).

Process-contract tests use a clearly identified compiler test double. A local
smoke check additionally compiled a `puts` program using upstream
`cl65 V2.19 - Git e11fb5c`, producing a BIN AppleSingle payload at `$0803`.
An additional smoke check built an `apple2enh` C program through ProjectBuilder,
packaged the BIN at `$0803`, booted ProDOS through its STARTUP program in MAME,
and passed a text-output assertion. Test each program in its intended target and
DOS/ProDOS environment as well.
